---
id: KB-1050
title: Pods in CrashLoopBackOff
category: cloud_infrastructure
access: internal
team: Cloud Platform
---
Symptoms: a Kubernetes deployment keeps restarting or stays in CrashLoopBackOff.

Run kubectl describe pod and read the last exit code. Exit code 137 means the container was killed for exceeding its memory limit.

Read the previous container's logs with kubectl logs --previous. Missing configuration or a failed secret mount commonly stops an app during startup.

If a rollout caused it, run kubectl rollout undo to return to the last good revision, then fix the issue in the pipeline.
