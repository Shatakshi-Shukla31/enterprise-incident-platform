id: KB-1505
title: Finding why one query is slow
category: database
access: internal
team: Database Administration
---
Symptoms: one report or endpoint is slow while the rest of the database is healthy.

Run EXPLAIN (ANALYZE, BUFFERS) on a replica, because ANALYZE really executes the statement.

Look for sequential scans on large tables and for row estimates far from the actual counts.

Add an index that matches the filter and sort columns.

If estimates are wrong, run ANALYZE to refresh the statistics.

Use pg_stat_statements to find the queries that take the most total time.
