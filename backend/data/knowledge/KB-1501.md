---
id: KB-1501
title: Restoring data deleted or changed by mistake
category: database
access: internal
team: Database Administration
---
Symptoms: rows or a table were deleted, or an UPDATE ran without a WHERE clause and changed the wrong records.

Stop writes to the affected table if you can, and note the exact time of the mistake.

Restore a copy to a separate server at a point just before the mistake, using the base backup and WAL archive.

Never restore over production. Export only the affected rows and load them back under change control.

Have the data owner confirm the result before closing the incident.
