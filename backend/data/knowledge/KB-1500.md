id: KB-1500
title: Deadlock errors in the database
category: database
access: internal
team: Database Administration
---
Symptoms: the application logs deadlock detected or SQLSTATE 40P01, and transactions are aborted at random.

A deadlock happens when two transactions each wait for a lock the other holds, so the database aborts one of them.

Read the server log, which shows both statements involved.

Take locks in the same order everywhere, keep transactions short, and index foreign keys.

Applications should retry a transaction that was aborted this way.

A deadlock clears by itself. If sessions stay stuck, it is blocking, which has its own article.
