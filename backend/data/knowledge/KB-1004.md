---
id: KB-1004
title: Requesting and verifying firewall path changes
category: network
access: internal
team: Network Operations
---
Symptoms: connections between two services time out while each service is healthy on its own.

Capture source, destination, port and protocol before anything else. Use a TCP connection test from the source host to separate a blocked path from a stopped listener.

Check the firewall deny logs for the destination address. A deny entry confirms a policy block, so raise a change request with the business justification.

If no deny entry exists, look for asymmetric routing or a NAT rule change. Emergency rule changes need Security Operations approval and must be reviewed within 24 hours.
