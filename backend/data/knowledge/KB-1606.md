---
id: KB-1606
title: Rolling back a bad deployment
category: cloud_infrastructure
access: internal
team: Cloud Platform
---
Symptoms: errors or latency jumped straight after a release, and you need the previous version back.

Compare the release time with the error graph. If they line up, roll back before investigating.

Run kubectl rollout undo deployment/name, then watch kubectl rollout status.

Check for database migrations first, because old code may not run on the new schema.

Turning off a feature flag is faster if the change sits behind one.
