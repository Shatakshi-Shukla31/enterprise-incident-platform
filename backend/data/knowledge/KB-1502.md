id: KB-1502
title: Planned and emergency database failover
category: database
access: internal
team: Database Administration
---
Symptoms: the primary database server is down, or maintenance requires moving to a standby.

Check replication lag first, because promoting a standby that is behind loses recent writes.

Fence the old primary so that two servers can never accept writes at once.

Promote the standby, then repoint applications through the connection endpoint or DNS name.

Rebuild the old primary as a standby using pg_rewind or a fresh base backup.

The Promote read replica runbook needs a manager's approval.
