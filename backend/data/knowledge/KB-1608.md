---
id: KB-1608
title: Applying a rotated secret to a running service
category: cloud_infrastructure
access: internal
team: Cloud Platform
---
Symptoms: a Kubernetes secret was updated but the application still uses the old password, or authentication fails after an expiry.

Environment variables taken from a secret do not change in a running pod, so restart it with kubectl rollout restart.

Files mounted from a secret update after a delay, but the application must reload them.

Confirm the new value works, then remove the old credential.

Set an expiry alert 30 days ahead.
